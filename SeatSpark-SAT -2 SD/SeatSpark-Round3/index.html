ROUND 3 · HIGH-LEVEL DESIGN

Built around a reliable booking flow.

This runnable front-end demo illustrates the user journey and the main HLD components. It stores demo bookings in this browser only.

🧑‍💻

1. Client UI

Browse events, select seats, view reservations and cancel a demo booking.

🔌

2. REST API layer

In a full system: event search, seat availability, reservation, payment and cancellation endpoints.

🗄️

3. Database

PostgreSQL stores users, events, seats, reservations and payment status with unique seat constraints.

⚡

4. Cache

Redis can cache popular event listings and short-lived seat availability to reduce read load.

🔒

5. Booking safety

Use transactions, seat locks or expiring holds to prevent two customers booking the same seat.

📨

6. Notifications

A queue sends booking confirmation email/SMS after a successful reservation.

Browser→REST API→Booking service→PostgreSQL↔ Redis cacheBooking event → Queue → Email/SMS

Scope note: This is a front-end demonstration, not a production ticketing backend. Real multi-user booking, authentication and payments require server-side implementation and configured services.
